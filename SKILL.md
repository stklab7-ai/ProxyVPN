# ProxyVPN Development Guide

Этот навык (skill) определяет правила работы с кодовой базой проекта ProxyVPN.

## 🎯 Главная цель проекта
ProxyVPN — это Android-приложение (Kotlin + Jetpack Compose + NDK), объединяющее различные ядра (Xray, Tun2socks, ByeDPI, Shadowsocks) для организации VPN. 
**Ключевая задача проекта:** обеспечение надежного обхода блокировок, ТСПУ (Технические средства противодействия угрозам) и систем DPI (Deep Packet Inspection) в России, с особым упором на мобильный интернет (Мегафон, МТС, Tele2, Beeline).

## 🛠️ Основные правила работы (CRITICAL)

1. **Прямое редактирование кода (Без мусора)**
   - В проекте накопилось много Python-скриптов (`fix_*.py`, `add_*.py`), которые ранее использовались для патчинга файлов. **БОЛЬШЕ ТАК НЕ ДЕЛАТЬ.**
   - Для изменения кода используйте инструменты прямого редактирования (`replace_file_content`, `write_to_file`).
   - Если для выполнения задачи вы создаете временные файлы, скрипты или логи — **обязательно удаляйте их за собой** после успешного завершения задачи. Соблюдайте чистоту в репозитории.

2. **Фокус на анти-DPI технологиях**
   - При добавлении новых протоколов или модификации текущих (Xray, ByeDPI) учитывайте актуальные методы блокировок в РФ.
   - Используйте современные методы защиты: VLESS + XTLS-Reality, Shadowsocks-2022, фрагментация пакетов (fragment), модификация ClientHello (ByeDPI/CIADPI), настройка кастомного MTU.

3. **Сборка и проверка**
   - После внесения изменений в код или манифест, агент обязан запустить сборку APK для проверки отсутствия ошибок компиляции.
   - Команда сборки: `.\gradlew assembleDebug` (или `assembleRelease`).
   - Сообщите пользователю об успешной сборке и пути к готовому `.apk` файлу.

4. **Обновление бинарных компонентов**
   - В корне проекта присутствуют скрипты PowerShell (например, `download_xray.ps1`, `download_ss.ps1`). 
   - Используйте их, когда пользователь просит обновить ядро (Xray, Shadowsocks и др.) до последней версии.

## 📁 Структура проекта
- `app/src/main/java/com/proxyvpn/` — Исходный код Android-приложения (Kotlin).
- `app/src/main/jni/` — NDK/C++ код для взаимодействия с бинарниками.
- `app/build.gradle` — Настройки сборки Gradle (включает NDK arm64-v8a).

## 🔄 Стандартный рабочий процесс (Workflow)
1. Пользователь ставит задачу (например: "обнови параметры фрагментации ByeDPI").
2. Агент находит нужные `.kt` или `.cpp` файлы и напрямую редактирует их.
3. Агент выполняет тестовую сборку через `.\gradlew assembleDebug`.
4. Агент удаляет любые временные файлы ("мусор"), которые мог создать в процессе работы.
5. Агент отчитывается о результате.
